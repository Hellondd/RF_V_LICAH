# ✅ Чеклист тим лида — что сделать прямо сейчас

## ШАГ 1 — Создать репозиторий на GitHub

1. Зайти на https://github.com → **New repository**
2. Название: `russia-v-licah`
3. Описание: `Интерактивный просветительский сайт «Россия в лицах» ко Дню России`
4. Видимость: **Public** (нужно для демонстрации) или Private
5. ✅ Добавить README — **НЕТ** (мы загрузим свой)
6. ✅ .gitignore — **НЕТ** (у нас свой)
7. Нажать **Create repository**

---

## ШАГ 2 — Загрузить начальную структуру (первый коммит)

```bash
# На своём компьютере:
git clone https://github.com/ВАШ-ЮЗЕРНЕЙМ/russia-v-licah.git
cd russia-v-licah

# Скопировать все файлы из этого архива в папку
# Затем:
git add .
git commit -m "init: project structure, README, .env.example, .gitignore"
git push origin main
```

---

## ШАГ 3 — Настроить ветки

```bash
# Создать ветку разработки
git checkout -b dev
git push origin dev

# Установить dev как ветку по умолчанию для PR:
# GitHub → Settings → Branches → Default branch → dev
```

### Правило работы с ветками для команды:

```
main        ← только финальная рабочая версия
dev         ← основная ветка разработки
feature/*   ← каждый делает свою фичу здесь

Пример: feature/auth, feature/regions, feature/quiz
```

- Branch name: `main`
- ✅ Require a pull request before merging
- ✅ Require at least 1 approving review (тим лид)

## ШАГ 7 — Договориться о правилах коммитов

Отправь команде это сообщение:

```
Правила работы с Git:

1. Работаем в ветках feature/название-задачи
2. Коммиты на английском, формат: тип: описание
   Примеры:
   - feat: add regions list page
   - fix: fix quiz score calculation
   - docs: update README
   - style: fix mobile layout

3. Перед пушем — git pull origin dev
4. Готовую фичу → Pull Request в dev
5. Тим лид ревьюит и мержит
6. Коммитить каждый день, даже если немного сделано
```

## ⚠️ Частые ошибки — не допусти

| Ошибка | Что делать вместо |
|--------|-------------------|
| Один коммит в конце | Коммитить каждый день |
| .env файл в Git | Добавить в .gitignore |
| Работать в main | Всегда в feature/* ветках |
| Пароли в коде | Использовать .env |
| Молчать о проблемах | Писать в рабочий чат сразу |
