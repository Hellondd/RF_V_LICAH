## 👥 Роли и задачи

### 1. Backend-разработчик (API, аутентификация, бизнес-логика) (ЗАТОНСКИЙ ЕГОР)

- [ ] **Модели SQLAlchemy**  
  Создать в `app/models/` классы: `User`, `Region`, `Person`, `Achievement`, `QuizQuestion`, `QuizAnswer`, `QuizResult`, `Postcard`, `Source`.  
  Указать типы колонок, связи (`ForeignKey`), индексы.

- [ ] **`app/core/security.py`**  
  Реализовать `get_password_hash`, `verify_password` (passlib), `create_access_token` (python-jose). Взять `SECRET_KEY` из `config.py`.

- [ ] **Миграции Alembic**  
  - `alembic init migrations` (если не выполнено).  
  - `alembic revision --autogenerate -m "init tables"`  
  - `alembic upgrade head`

- [ ] **Эндпоинты авторизации** (`/api/v1/auth`)  
  `POST /register` (name, email, password → хеш, роль user по умолчанию).  
  `POST /login` (email, password → JWT).  
  `GET /me` (текущий пользователь по токену).

- [ ] **CRUD регионов** (`/api/v1/regions`)  
  `GET /` (пагинация), `GET /{id}`, `POST /` (только админ), `PUT /{id}`, `DELETE /{id}`.

- [ ] **CRUD персоналий** (`/api/v1/persons`)  
  Аналогично регионам. Добавить фильтр по `category` (query‑параметр).

- [ ] **CRUD достижений** (`/api/v1/achievements`)  
  Аналогично персоналиям.

- [ ] **Викторина** (`/api/v1/quiz`)  
  `GET /questions` (все вопросы + варианты ответов).  
  `POST /submit` (принимает массив `{question_id, selected_answer_ids}`, вычисляет баллы, возвращает `score`, `max_score`, `level`).  
  `GET /results` (история авторизованного пользователя).  
  `GET /leaderboard` (топ-10 по баллам).

- [ ] **Открытки** (`/api/v1/postcards`)  
  `GET /templates` (захардкодить 3 шаблона с id и названием).  
  `POST /` (создание: `template_id`, `sender_name`, `text` → сохранить в БД, вернуть заглушку `image_url`).

- [ ] **Админ‑эндпоинты** (`/api/v1/admin`)  
  `GET /stats` (количество записей в основных таблицах).  
  `GET /users` (список пользователей с пагинацией, только админ).

- [ ] **Загрузка файлов** (`/api/v1/upload`)  
  `POST /upload` (принимает файл, сохраняет в `uploads/`, возвращает URL). Проверка размера и типа.

### 2. Frontend-разработчик 1 (Главная, История, Регионы, Персоналии) (БОДРОВ ДАНИИЛ)

- [ ] **Главная страница**  
  Баннер, кнопки быстрого перехода («История», «Регионы», «Викторина», «Открытка»), блок «Сегодня Россия — это...» (карточки категорий: люди, регионы, культура, наука, технологии, достижения).

- [ ] **История Дня России**  
  Таймлайн (вертикальный или горизонтальный) с событиями: 1990, появление праздника, переименование, современное значение. У каждого события — год, описание, иконка.

- [ ] **Карта регионов**  
  Список регионов карточками (название, округ, краткое описание, изображение). Клик → страница региона с полными данными (описание, факты, культура, достижения).

- [ ] **Россия в лицах**  
  Список персоналий карточками (ФИО, категория, регион, краткий вклад). Фильтр по категории (выпадающий список). Клик → полная карточка личности (биография, вклад, важность, источник).

- [ ] **Адаптивная вёрстка**  
  Медиа‑запросы для мобильных, планшетов, десктопа. Все страницы должны корректно отображаться на всех разрешениях.

### 3. Frontend-разработчик 2 (Достижения, Многонациональная Россия, Викторина, Открытка) (БЕЛЫЙ ДАНИИЛ)

- [ ] **Достижения России**  
  Карточки достижений (заголовок, категория, год, краткое описание, иконка). Фильтрация по категориям (выпадающий список или кнопки). Пагинация.

- [ ] **Многонациональная Россия**  
  Информационные блоки о народах, традициях, праздниках, ремёслах, кухне. Можно сделать вкладки по категориям.

- [ ] **Викторина**  
  Страница с вопросами (по одному или все на одной странице). Отображение вариантов: radio (один ответ), checkbox (несколько). Подсчёт баллов на фронте (пока без API) или с бэкендом после реализации. Экран результата (уровень, баллы, кнопка «Пройти ещё раз»).

- [ ] **Создание открытки**  
  Выбор шаблона (превью), поля «Имя отправителя» и «Текст поздравления». Предпросмотр. Кнопка «Скачать» — генерирует PNG (html2canvas + jsPDF) или отправляет запрос на бэкенд.

### 4. Fullstack / интеграция (связка, ИИ‑помощник, личный кабинет) (БОЛЬШАКОВ ЕГОР)

- [ ] **HTTP‑клиент**  
  Настроить axios (базовый URL, перехватчики для добавления JWT‑токена из localStorage).

- [ ] **Авторизация на фронте**  
  Страницы логина и регистрации. Сохранение токена, получение текущего пользователя (`/me`). Защита маршрутов (личный кабинет, админка).

- [ ] **Личный кабинет**  
  Отображение результатов викторины пользователя (список пройденных квизов: дата, баллы, уровень) и его открыток (дата, текст, превью).

- [ ] **Поиск по сайту**  
  Глобальный поиск в шапке — фильтрация регионов и персоналий на клиенте (или через бэкенд, если будет эндпоинт `/search`).

- [ ] **ИИ‑помощник**  
  Чат‑заглушка (иконка → модальное окно). Ответы на заранее заготовленные вопросы (о Дне России, регионах, поздравления, помощь с открыткой). Без подключения внешнего API.

### 5. БД + контент + тестирование (модели, наполнение, тесты, документация) (ИВАНЕН МАКАР)

- [ ] **Согласование моделей**  
  Проверить, что все поля из ТЗ присутствуют в моделях (уточнить с бэкенд‑разработчиком). При необходимости скорректировать.

- [ ] **Тестовые данные**  
  Подготовить контент (CSV/JSON) для seed‑скрипта:  
  - 10+ регионов (название, округ, столица, описание, факты, культура, достижения, изображения).  
  - 20+ персоналий (ФИО, категория, регион, биография, вклад, важность, источник).  
  - 15+ достижений (заголовок, категория, описание, год, источник).  
  - 15+ вопросов викторины (текст, тип, варианты, правильные ответы, пояснение).

- [ ] **Seed‑скрипт**  
  Написать `seed.py`, который загружает эти данные в БД через SQLAlchemy. Запуск: `docker-compose exec backend python seed.py`.

- [ ] **Функциональное тестирование**  
  Заполнить таблицу из `docs/testing.md` (24 пункта). Отметить статус (✅ ❌ 🔄), зафиксировать баги.

- [ ] **Документация**  
  `user-guide.md` — инструкция для обычного пользователя (регистрация, викторина, открытка).  
  `admin-guide.md` — как управлять контентом (добавление регионов, персоналий, достижений, вопросов).

## 📌 Процесс работы

1. **Каждый участник** создаёт от ветки `dev` свою ветку `feature/имя-задачи`.
2. **Коммиты** на английском: `feat: add user model`, `fix: fix login error`.
3. **Pull Request** в `dev` — тимлид ревьюит и мержит.
4. **Ежедневные стендапы** — кратко: что сделал, что делаешь, есть ли блокеры.
5. **Тестирование** — после выполнения своей части разработчик проводит минимальное тестирование и сообщает о результатах.
